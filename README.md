## **❓ What is BBB?**
**BetterBouncyBlocks** brings dynamic **trampoline mechanics** to your Minecraft server! With **BBB**, you can choose **any block material** into a **powerful launchpad** or set up **consumable single-use trampolines**. This **lightweight** and **highly customizable** plugin is built for Paper 1.21, offering **excellent performance**, **seamless integration** and **high stability**.

## **🌟 Key Features:**

🔧 **Permanent Bouncy Blocks**: Easily define which block material acts as a permament trampoline

🍬 **Consumable Bouncy Blocks**: Set up one-time use blocks that disappear immediately after launching a player

💰 **Economy Integration**: Allow players to purchase consumable blocks in-game with `/bbb buy` or easily hand out consumable blocks to players using `/bbb give`

🚀 **Customizable Launch Height**: Fine-tune exactly how high players should be launched

🛡️ **Integrated Fall Damage Protection**: BetterBouncyBlocks automatically protects players from fall damage after a bounce for a customizable duration

🗺️ **WorldGuard Region Support**: Restrict trampoline mechanics exclusively to specific WorldGuard regions (e.g., spawn, lobby...)

💬 **Customizable Messages**: Tailor nearly all plugin messages to match your server's style. You can use both modern MiniMessage tags and legacy color codes at the same time!

🔔 **Update Notifications**: An automatic update checker can be configured to notify you in the console or directly in-game (or both) when a new version is available. It can be easily toggled on/off in the configuration

## ️**🛡️ Commands & Permissions:**
`/bbb reload` | `betterbouncyblocks.reload`

`/bbb give <player> <amount>` | `betterbouncyblocks.give`

`/bbb buy <amount>` | `betterbouncyblocks.buy`

`betterbouncyblocks.use` (allows players to use standard bouncy blocks (default true))

`betterbouncyblocks.use.consumable` (allows players to use consumable bouncy blocks (default true))

`betterbouncyblocks.update` (for in-game update notifications)

`betterbouncyblocks.admin` (parent permission for all permissions)

## **❓ Q&A:**
**Why is the compiled plugin (JAR file) larger than the source code on GitHub?**

Our plugin includes dependencies like **bStats** to gather anonymous usage statistics. When the plugin is compiled into a single JAR file, the bStats library (along with all its own dependencies) is packaged directly into the final plugin file. This process, called 'shading', makes the plugin self-contained which naturally increases the overall file size compared to just the raw source code.
